# AGENTS.md — Quadrant (Eisenhower Matrix PWA)

> **This is the single source of truth for any agent (Antigravity, Claude Code, Cursor, Windsurf) working in this repo.** Read it fully before your first edit. Re-read sections relevant to your current task. If a rule conflicts with a user instruction, surface the conflict — do not silently ignore the rule.

## 0. Mission

Build **Quadrant**, a cross-device Eisenhower Matrix PWA. See `docs/PRD.md` for the full product spec. Optimize for: (1) frictionless capture, (2) reliable offline-first sync, (3) WCAG AA accessibility, (4) hand-off-ready code quality.

## 1. Tech Stack (do not deviate without an ADR)

- Next.js 15 (App Router) + TypeScript **strict**
- Tailwind CSS v4 + shadcn/ui
- Zustand (client state) + TanStack Query v5 (server cache)
- dnd-kit (drag-and-drop)
- Dexie.js (IndexedDB outbox + cache)
- Supabase (Auth + Postgres + Realtime)
- Serwist (service worker)
- Vitest + Playwright
- Vercel (deploy)

## 2. Code Standards

- TypeScript **strict mode**, no `any` without an inline `// rationale` comment.
- **Functional components only** — no classes.
- **Named exports** for components; default export only for Next.js page/layout files.
- `interface` for object shapes; `type` for unions/intersections.
- JSDoc on every exported function, including a one-line `@example`.
- No barrel files (`index.ts` re-exports) — they break tree-shaking.
- No inline styles. Use Tailwind utilities or `cva` variants.
- Server components by default; mark `'use client'` only when the file needs hooks, browser APIs, or event handlers.

## 3. Folder Boundaries (which agent edits what)

| Path | Purpose | Modify when |
|---|---|---|
| `app/` | Routes, server components | Adding pages or layouts |
| `components/ui/` | shadcn primitives (auto-generated) | Running `npx shadcn add` only |
| `components/quadrant/` | Domain components | Building features |
| `lib/db/` | Dexie schema, outbox | Sync logic changes |
| `lib/supabase/` | Auth + data clients | Backend integration |
| `supabase/migrations/` | SQL migrations | Schema changes (use `supabase-migration` skill) |
| `tests/` | All test code | Whenever you ship a feature |

**Never** edit `components/ui/` by hand — it's regenerated by shadcn CLI.

## 4. Definition of Done (every PR)

- [ ] Types pass: `pnpm typecheck`
- [ ] Lint passes: `pnpm lint`
- [ ] Unit tests pass: `pnpm test`
- [ ] E2E happy-path passes: `pnpm test:e2e`
- [ ] Lighthouse PWA ≥ 95, A11y ≥ 95, Performance ≥ 90 (use `pwa-validator` skill)
- [ ] No new `console.log` calls in shipped code
- [ ] `.env.example` updated if new env vars were added
- [ ] Walkthrough artifact attached (Antigravity browser recording)

## 5. Antigravity Artifact Protocol

For any task the user dispatches, you **must**:

1. Generate `artifacts/plan_<task_id>.md` with: goal, affected files, risks, test strategy.
2. Generate `artifacts/implementation_plan_<task_id>.md` with: ordered steps, SQL diffs (if any), and a rollback note.
3. **Pause and ask the user to review both artifacts before writing code.** Do not skip this step.
4. After execution, generate `artifacts/walkthrough_<task_id>.md` with screenshots from the built-in browser proving the user story works.
5. Save logs to `artifacts/logs/<task_id>.log` for any failed test or terminal command.

## 6. Things You Must Never Do

- ❌ Use `localStorage` for auth tokens — use Supabase SSR cookies.
- ❌ Commit secrets. Re-check `.env.example` and `.gitignore`.
- ❌ Bypass RLS by using the Supabase service-role key in client code.
- ❌ Add a `<form>` tag without an `onSubmit` handler that calls `e.preventDefault()`.
- ❌ Introduce a new top-level dependency without justifying it in the implementation plan.
- ❌ Skip the artifact review step in §5.
- ❌ Modify migration files that are already merged to `main` — write a new migration instead.

## 7. Communication Style

- Be terse. Engineers read this; salesmanship wastes their time.
- Surface trade-offs explicitly. ("I chose X over Y because...")
- When unsure, write the question into the plan artifact and pause — do not guess.

- `/add-feature <description>` — vertical-slice a new feature with plan → impl → test → walkthrough
- `/verify` — run the full Definition-of-Done gauntlet
